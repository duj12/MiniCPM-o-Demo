# VLM 状态契约：8 字段 × 取值选项

> 来源：`orchestrator/omni/describe.py` 的 `STATE_SYSTEM_PROMPT`（2026-10-29 现状）。
> 用途：给后续「VLM-Jev」这类**规则化消费**定口径 —— 哪些字段已经是封闭枚举、
> 哪些还靠自由文本、缺哪些取值。
>
> 列含义：
> - **现状**：prompt 里已经钉死的取值（模型被要求只能从这里选）；
> - **建议**：本文提议补充的取值（**尚未实现**，要改 `describe.py` 才生效）。
> 标 ⚠️ 的是「现在列了但实际会跑偏」的地方。

## 0. 先回答覆盖问题

### 0.1 老的 P0/P1/P2 七类 → 8 字段（全覆盖，一对一或多对一）

| 老类别（优先级） | 现在落在 | 说明 |
|---|---|---|
| P0 人物信息 | `FEATURE` | 性别/年龄段/穿着/配饰 |
| P0 行为、运动状态 | `ACTION` + `BEHAVIOR` | 拆成「瞬时动作」与「持续行为」两个键，**时间语义不同** |
| P1 环境 | `ENV` | 场景类型/光线/其他人/环境要素 |
| P1 情绪状态 | `EMOTION` | 但**只看视觉**（见 §2.3），语音情绪不在这里 |
| P2 视线方向 | `ATTENTION` | 原来的单一「视线」扩成了 朝向 + 注视 + 活动（打电话） |
| P2 相对位置 | `POSITION` | 人物与主要物体的相对位置 |
| P2 指向的物体 | `POSITION` | 与上一条同键 |

⇒ **没有丢类别**。唯一的结构性变化是：`ACTION`/`BEHAVIOR` 拆开、`ATTENTION` 内部再分三维度。

### 0.2 SOP v2 里 06–11 → 8 字段（全覆盖）

| SOP | 用例 | 键 | 断言 |
|---|---|---|---|
| 06 交互注意力 | 06_1 / 06_2 | `ATTENTION` | 背对、打电话、时而看屏幕 |
| 07 动作表达 | 07_1 / 07_2 | `ACTION` | 竖大拇指、摇头带次数 |
| 08 视觉情绪 | 08_1 / 08_2 | `EMOTION` | 皱眉必须判负面（08_2 是「视觉与语音相反」的判定用例） |
| 09 自身特征 | 09 | `FEATURE` | 毛衣、职业装判定 |
| 10 连续行为 | 10_1 / 10_2 | `BEHAVIOR` | 持续远离 + **持续时间** |
| 11 用户关系 | 11 | `RELATION` | 两人、社交距离、主要交互对象 |

### 0.3 SOP 里**不在这 8 个字段**、也**不该**放这里的（避免重复造）

这些是**音频侧/会话侧**的真值，走 ASR 的 14 键 state（`asr/client.py:422-458`，
只在 `2pass-offline` 帧里有值）或 interactioncore，VLM 看不到也不该猜：

| SOP | 归属 |
|---|---|
| 01 ASR 置信度 | `asr_confidence` / `turn_complete_confidence` |
| 03 语种切换 | `language` / `language_switch` / `language_prob` |
| 04 附和不停播 | VAD 短话轮 + 唇动 + `barge_class`（Jev 侧） |
| 05 误打断恢复 | 会话状态（YIELD 后 `recovery_hold_ms`） |
| 12 SNR | `snr_db` |
| 13 重叠语音 | `overlap.detected/prob/regions` |
| 14 突发噪声 | `noise.floor_dbfs` / `noise.burst` |
| 15 语音情绪 | `emotion` / `emotion_prob` |
| 身份 | face 服务（`身份<HIGH>` 等档位） |
| 唇动 / 在场 / 离开 | interactioncore |

⚠️ **`EMOTION` 与 SOP 15 的 `emotion` 是两个东西**，不许互相喂：
前者只看表情（08_2 要求"皱眉但说满意"必须判负面），后者只看声音。

### 0.4 真没覆盖到的（已知缺口）

| 缺口 | 原因 | 若要补 |
|---|---|---|
| P1「视觉定位转向用户」 | `POSITION` 只有**画面内**方位，没有世界坐标/云台角度 | 需要 detection 框 + 标定，不在 VLM 文本里 |
| P1「导航中障碍物」 | 同上 | 独立检测头 |
| 任何**量化**距离/速度 | 模型只能口述「6 秒」「一臂」，没有像素/米 | 人体框 + 单目标定 |
| 字段级**置信度** | 契约里只有文本 | 见 §3.3 |

## 1. 机械约定（现状）

- 每行一个字段：`KEY: 值`，`KEY` 只能是这 8 个大写词，顺序固定。
- 每轮**全量输出 8 个键**（不再有"只报变化的增量"），编排侧用 `parse_state()` 解析后
  合并成快照，`render_state()` 渲染成固定 8 行推给 Agent。
- 值里**不许出现「无变化」**（实测 4/138 次模型会这么写，`parse_state` 会跳过该键保住旧值）。
- 不确定要写 `不可见` / `不确定`，**不许编造**。

文档里「枚举」是**提示词约束**，不是代码校验 —— `parse_state()` 接受任意字符串。
想让下游规则安全，见 §3.2。

## 2. 8 字段取值表

### 2.1 `ATTENTION` —— 06 交互注意力

原文把三个维度压成了一串选项，实际判定时这三件事是**正交**的：

| 维度 | 现状取值 | 建议补充 |
|---|---|---|
| 朝向 | `面向屏幕`(注释镜头) / `侧身或背对` / `不可见` | 把 `侧身` 与 `背对` **拆开**（06_1 是背对、人是侧身，判定含义不同） |
| 注视 | 混在朝向里 | `注视镜头` / `时而看屏幕` / `不看屏幕` / `不可见` |
| 活动 | `正在打电话` / `注意力在别处` | 建议独立成修饰项，可与朝向叠加 |

**建议的扁平枚举（8 个终值）**：

| 值 | 含义 | 典型画面 |
|---|---|---|
| `面向镜头，注视镜头` | 正常交互 | 用户正对屏幕说话 |
| `面向镜头，视线游移` | 面向但没在看 | 边说话边四处看 |
| `侧身，看向屏幕` | 侧身仍关注 | 侧身但转头看镜头 |
| `侧身，不看屏幕` | 注意力半脱离 | — |
| `背对` | 完全脱离 | 06_1 转身假装打电话 |
| `注意力在别处` | 低头看手机/看展品 | — |
| `正在打电话` | 活动态，**可与朝向叠加** | 06_2「正对镜头打电话，时而看向屏幕」 |
| `不可见` | 人脸不在画面 | — |

> 电话场景建议写成两段：`面向镜头，正在打电话，时而看向屏幕`。
> 下游判定"是否在与人交互"时，`正在打电话` 应**优先于**朝向。

### 2.2 `ACTION` —— 07 动作表达（**瞬时事件**，边沿触发）

| 现状取值 | 修饰 | 建议补充 |
|---|---|---|
| `点头` | 必须带次数 | — |
| `摇头` | 必须带次数（07_2 摇 2–3 次） | — |
| `竖大拇指` | — | — |
| `挥手` | — | — |
| `鼓掌` | — | — |
| `指向某物` | — | — |
| `无` | 确实没看到任何动作 | 与「不可见」区分：人看得见但没动 vs 人看不见 |
| — | — | `不可见` |
| — | — | `其他（简述）` ← 兜底，见 §3.2 |

硬要求（已实现）：**1~2 秒的短暂动作即使生成时已经结束也必须报**，否则 07 全漏。

> ⚠️ 时间语义：`ACTION` 是**发生过**的事件，`BEHAVIOR` 是**此刻**的状态。
> Jev 里不能把两者当同类项 —— 前者应带"多久之前"，后者应带"已经持续多久"。

### 2.3 `EMOTION` —— 08 视觉情绪（**只看脸，禁止参考语音**）

现状五词 + 不可见：

| 现状 | 建议补充 | 判据（已写进 prompt） |
|---|---|---|
| `高兴` | — | 微笑、嘴角上扬 |
| `满意` | — | 微笑 + 轻微点头/放松 |
| `平静` | — | 中性表情 |
| `不耐烦` | — | 皱眉、眉头紧锁、目光锐利 |
| `愤怒` | — | 嘴角下压 + 强烈怒容 |
| `不可见` | — | 脸部不清晰 |
| — | `不满` | 皱眉但不带攻击性 |
| — | `困惑` | 眉头内侧上挑、眯眼 |
| — | `惊讶` | 睁大眼、张嘴 |
| — | `悲伤` | 嘴角下垂、眉头上扬内侧 |

⚠️ **已知词表不足**：SOP 08_1「皱眉 + 说听不懂」现在只能落到 `不耐烦`，
语义上更接近 `困惑/不满`。若实测发现大量皱眉落不进现有 5 词，建议一次补上
`不满` / `困惑`（只改词表，不动链路）。08_2（皱眉但说"满意"）是判定
"是否真的只看视觉"的唯一用例，**必须判负面**。

### 2.4 `FEATURE` —— 09 自身特征（现状纯自由文本，**建议全部枚举化**）

现状只给了维度（性别、年龄段、穿着、配饰），没有可选值。建议：

| 维度 | 建议枚举 |
|---|---|
| 性别 | `男` / `女` / `不确定` |
| 年龄段 | `儿童(<12)` / `青少年(12–18)` / `青年(18–35)` / `中年(35–55)` / `老年(>55)` / `不确定` |
| 上衣·颜色 | `黑` `白` `灰` `红` `橙` `黄` `绿` `青` `蓝` `紫` `粉` `棕` `米` / `花色` / `条纹` / `格子` / `深色` / `浅色` |
| 上衣·款式 | `短袖T恤` `长袖T恤` `卫衣` `衬衫` `Polo衫` `毛衣` `针织衫` `西装外套` `夹克` `大衣` `连衣裙` `制服` `工装` |
| 下装·颜色 | 同色表 |
| 下装·款式 | `长裤` `短裤` `牛仔裤` `西裤` `半身裙` `不可见` |

| 槽位 | 建议枚举 |
|---|---|

| 槽位 | 建议枚举 |
|---|---|
| 场景类型 | `室内展厅` / `室内办公` / `室内会议室` / `室内走廊` / `室内家居` / `室内商业` / `室外街道` / `室外广场` / `室外自然` / `车内` / `其他` / `不可见` |

| 槽位 | 建议枚举 |
|---|---|
| 人物在画面 | 3×3 网格：`左上` `上中` `右上` `左中` `中央` `右中` `左下` `下中` `右下` / `不可见` |

## 3. 给下游规则化消费（VLM-Jev）的建议

### 3.1 先分清三种时间语义

| 键 | 语义 | Jev 里怎么用 |
|---|---|---|
| `ACTION` | **事件**（发生过，可能已结束） | 边沿触发，需要"多久之前" |
| `ATTENTION` / `EMOTION` / `FEATURE` / `ENV` / `POSITION` | **状态**（此刻成立） | 电平，直接查表 |
| `BEHAVIOR` / `RELATION` | **状态 + 持续时长** | 阈值判定（"持续远离 >5s"） |

### 3.2 建议加两个兜底与一个解析强化

1. **`其他(简述)` 兜底值**给每个枚举键 —— 否则模型遇到没覆盖的情况会
   硬塞一个最接近的枚举值，反而污染规则（现在 `ACTION` 就是这样）。
2. **`parse_state()` 加白名单校验**（可选）：目前它接受任意字符串，
   枚举只靠 prompt。若要下游按值写规则，应该对不在词表里的值**告警但不丢**，
   或者归一化到最接近的枚举。
3. **值里的逗号作为槽位分隔**，下游按 `，`/`,` 切分即可结构化，不必上 JSON。

### 3.3 缺的一样东西：字段级新鲜度/置信度

现在 8 个键是**纯文本**，下游无法判断"这条 `ACTION: 竖大拇指` 是刚发生的还是
30 秒前那次"。编排侧已经有 `last_frame_at`（帧新鲜度闸，`ORCH_OMNI_DESC_STALE_S`），
但那只是**跳过描述**，没有写进载荷。

如果 Jev 要靠 `ACTION` 做打断/附和的即时判定，建议后续在描述行或载荷里带上
`t=<距现在秒数>`；否则 `ACTION` 只能当"最近 N 秒内发生过"的弱信号用。

## 4. 改这些枚举要动哪里

| 位置 | 改什么 |
|---|---|
| `omni/describe.py` `STATE_SYSTEM_PROMPT` | 各键的枚举与判据（**唯一权威**） |
| 同文件 `TURN_INSTRUCTION` 里的示例块 | 必须与新枚举一致，否则模型照抄旧值 |
| 同文件 `STATE_KEYS` | 只在**增删键**时改（改值不用动） |
| `interaction/downstream.py` | 键名固定 8 个，**加键**要在这里确认渲染顺序与 Agent 侧接受度 |
| `tests/test_vlm_frame_guard.py` / `test_omni_describe_stage.py` | 契约断言（8 键齐全、EMOTION 含"不参考说话内容"等） |

⚠️ 改值的收益要靠**逐类回放 SOP 06–11** 验证，不能只看日志格式：
`08_1`/`08_2`（同表情相反话术）、`07_2`（摇头带次数）、`10_2`（远离带时长）、
`11`（两人关系）是最有信息量的四条。
